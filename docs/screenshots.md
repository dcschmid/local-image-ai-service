# Refresh the documentation screenshots

The screenshots show the real Studio with bundled public examples. They use a separate demo archive, so opening a private image library is unnecessary. The example images were generated by the local service; the demo serves their published previews and does not run inference.

## Capture them again

From the repository root:

```bash
npm run build --prefix studio
python3 scripts/serve-docs-demo.py
```

Leave that process running. It prints its loopback URL; the default is port 7862. In another terminal, with the stack's Playwright launcher available:

```bash
mm-playwright open http://127.0.0.1:7862/studio/ --browser firefox
mm-playwright run-code --filename scripts/capture-docs.js
mm-playwright close
```

Stop the demo with Ctrl+C. Use `--port 0` if you need an automatically selected port, then use the URL it prints.

The capture script checks for the documentation-demo status before taking a screenshot. It uses real controls to load a preset and captures the workspace, example explorer and library at a 1600 × 1320 desktop viewport. It does not change the UI's styles or replace images in the page.

## What is safe to publish

The demo reads only the built Studio and its public `recipe-examples` files. It creates temporary copies of eight preview images and their public recipe settings. Its worker is stopped, no private configuration is loaded, and generation, model loading, favorites and deletion requests are blocked. GET routes and prompt composition remain available for inspecting the page.

The files under `docs/images/` are WebP screenshots. The gallery in the README and [example guide](examples.md) links directly to the already bundled example images, with their original inputs in [the manifest](../studio/public/recipe-examples/manifest.json).

Before replacing screenshots, check that:

- The selected preset matches the visible inputs and intended example.
- Images have finished loading and the page has no browser errors.
- No private image, prompt, path, API key or personal browser data is visible.
- Every published example is identified as a local model output, with its actual settings available.

Use `mm-playwright console error` to inspect browser errors and `git diff --check` for the documentation changes. Keep screenshots small enough to load comfortably in GitHub.
